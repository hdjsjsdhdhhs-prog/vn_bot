## Продукт

Telegram-бот для раздачи VPN-подписок (VLESS+Reality+Vision). Пользователь получает ссылку подписки
`/sub/...`, содержимое которой собирается из каталогов готовых источников (ProviderSource) выбранным Builder.
Бот **не регистрирует клиентов на VPN-панелях**: доступ — локальное состояние (строка подписки).

> Историческая справка: до миграции `051_remove_legacy_nodes` существовала подсистема VPN-узлов
> (Node / SubscriptionNode, панели 3x-ui и proxman, автомат синхронизации, панельный учёт трафика,
> пакеты `internal/vpn` и `internal/xui`). Она удалена целиком; терминов оттуда в коде больше нет.

## Сущности домена

- **Subscription** — подписка пользователя: связь Telegram-ID с планом, статусом и сроком, публичный токен.
  Состояния: `active` / `revoked` (прочие статусы зарезервированы). Необязательные ссылки: `ProviderSource`
  (покупка у провайдера) и `SubscriptionBuilder` (переопределение Builder для одной подписки).
  Поля `Devices` и `Ips` — JSON-массивы для аналитики клиентов.
- **Plan** — тарифный план (Free, Trial, платные). Несёт Builder по умолчанию (`subscription_builder_id`);
  лимитов трафика/устройств у плана больше нет.
- **Product** — платный продукт, привязанный к Plan (имя, цена, `DurationDays`).
- **Order** — событие покупки с трекингом оплаты. Состояния: `pending` / `paid` / `expired` / `canceled`.
- **ProviderSource** — внешний источник готовой подписки (URL, формат, заголовки, серверные учётные данные).
  Его каталог (`provider_source_entries`) только обогащает записи (страна и т. п.); живые данные источника первичны.
- **Subscription Builder** — собирает единую подписку из выбранных источников: правила по странам/узлам,
  переименование, порядок. Выбирается по приоритету: переопределение подписки → Builder плана.
- **Trial** — пробная подписка через план Trial + `trial_requests` (rate-limit по IP) и настройки trial в админке.
  Жизненный цикл: создание заявки → привязка к Telegram-ID (`BindTrialSubscription`, race-safe по `telegram_id < 0`).
  Просроченные анонимные trial физически удаляются (`CleanupExpiredTrials`).
- **Invite / Referral** — реферальная система: один код на реферера (`UNIQUE`-ограничение),
  подсчёт рефералов в `ReferralCache`, инвалидация кэша при привязке.

## Потоки (flows)

- **Subscription intake** — создание подписки: резолв Plan по имени (без хардкода ID) → запись подписки в БД →
  инвалидация кэшей → отдача ссылки. Внешней провизии нет. Удаление админом (`/del`) двухфазное:
  `revoked` (журналируется, `/sub` отвечает 404) → физическое удаление строки.
- **Subscription aggregation** — `subserver` определяет Builder, получает связанные включённые ProviderSource
  (bounded concurrency, сбой одного источника не фатален), детектит формат (JSON/Clash/Base64/Plain), применяет
  правила, агрегирует заголовки и кэширует ответ. Если ни один источник недоступен — ошибка
  (`ErrProviderSourceUnavailable`), без fallback на старый конвейер.
- **Order lifecycle** — `Create` → `Activate` (привязка/продление подписки) → `Expire`.
- **Фоновые задачи** — бэкап, heartbeat, очистка trial, истечение и напоминания подписок, повтор комиссий
  провайдера, прогрев клиентов, опциональный сетевой мониторинг. Синхронизации с панелями нет.

## Инфраструктурные понятия (тоже часть домена)

- **SubserverCache / SubscriptionCache / ReferralCache** — слои кэша (TTL/LRU). Инвалидируются при
  создании/удалении/привязке подписки и смене конфига Builder/источников.

## Открытые вопросы (кандидаты на углубление)

### Реализовано (обзор 2026-07-08/09, ветка `dev`) — историческая справка
- Кандидат 1 — узкий шов `DatabaseService` → пер-срезовые интерфейсы (`subserver`/`web`/`scheduler`), ADR-0001.
- Кандидат 2 — единый владелец двухфазного удаления (тогда `revokeAndDeprovisionThenDelete`; после миграции 051
  депровизионирования нет, остался `revokeThenDelete`).
- Кандидат 3 — вынос представления трафика (панельный трафик удалён миграцией 051).
- Кандидат 4 — классификация ошибок VPN за швом `Client` (подсистема удалена миграцией 051).

### Открыто
- Кандидат 1 — `subserver.Service` как pass-through над `Cache` (углубить или убрать).
- Кандидат 2 — timeout пролог применять один раз на диспетчеризации, а не копировать в каждый handler.

### Закрыто удалением (обзор 2026-07-09) — историческая справка
Кандидаты про circuit breaker XUI, шов `vpn.Client`, `httpx`-транспорт для `xui`/`proxman`, `buildProvision`
и `reconcileAndSyncNodes` потеряли предмет: соответствующий код удалён вместе с подсистемой узлов (миграция 051).
